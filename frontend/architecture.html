💻 1. How the Frontend Works

The frontend is built with pure Vanilla JavaScript (ES6+), HTML5, and responsive CSS with zero heavy framework bloat. It is split into specialized modular files inside frontend/js/:

apiClient.js Network Bridge

Unified REST client that automatically communicates with your cloud backend (https://nutriai-backend-y91i.onrender.com/api) or local fallback. Automatically attaches JWT tokens to requests.

state.js Single Source of Truth

Manages the central reactive store (appState). Contains getNutritionState() which computes the zero-based daily consumption totals and calories remaining.

authService.js Onboarding & Auth

Controls the 3-step onboarding wizard (registerUserFromWizard), client-side password hashing, validation rules, and user login state.

aiService.js AI Nutritionist

Intent-aware conversational AI. Classifies questions into Recipe Requests, Macro Queries, Food Substitutions, and queries the backend AI endpoint with clinical context.

charts.js Canvas Visuals

Native HTML5 Canvas chart renderer. Draws the Macro Doughnut Chart, 7-Day Caloric Intake Bar Chart, and Weight Trajectory Curves with zero external chart libraries.

app.js UI Controller

Master controller. Binds button clicks, modal transitions, topbar initial avatar (K/A), account dropdown popover, and food logging interactions.

⚙️ 2. How the Backend Works

The backend is a high-performance Python Flask REST API located in backend/ and deployed 24/7 on Render Cloud:

backend/app.py API Entrypoint

Initializes the Flask application, configures CORS headers, and registers Blueprints for /api/auth, /api/profile, /api/tracking, and /api/ai.

backend/database.py Database Engine

Creates and manages SQLite tables. Implements calculate_metabolic_targets() containing the exact Mifflin-St Jeor formulas (BMR, TDEE, Macro splits).

backend/routes/auth_routes.py Security

Handles /api/auth/register (salted SHA-256 password hashing), /api/auth/login (credential check), and /api/auth/me.

backend/routes/tracking_routes.py Tracking Ledger

Enforces zero-based consumption. Only checked/logged meals count towards consumed calories. Provides /api/tracking/state, /meal/toggle, /water, and /weight.

🗄️ 3. Where User Data is Stored

User data is stored across three persistent layers:

Layer Location What is Stored Inside Persistence
1. Primary Server Database backend/nutriai.db • users: ID, email, salted SHA-256 password hash.
• profiles: Age, sex, height, weight, goal, diet, cuisine, allergies.
• checked_meals: Explicitly checked daily meals.
• food_logs: Custom food entries.
• water_logs: Hydration totals.
• weight_history: Weigh-in check-in history. 		Permanent (Safe on Disk)
2. Browser Local Cache Browser localStorage • nutriai_jwt_token_v4: Active session token.
• nutriai_active_user_v3: Logged-in email.
• nutriai_users_db_v3: Instant offline cache for zero UI lag. 		Local Device (Instant Load)
3. 24/7 Cloud Host Render Cloud Server Hosts the live Python REST API 24/7 at https://nutriai-backend-y91i.onrender.com/api so your app never stops when your PC is turned off. Cloud 24/7
